# Push Swap

## Description

Push_swap is a highly straightforward algorithm project: data must be sorted. The goal is to sort a random set of integer values using two stacks (a and b) and a limited set of operations (such as sa, pb, ra, rra, etc.), achieving this with the lowest possible number of actions.

This project serves as a concrete introduction to algorithmic complexity (time and space). It requires implementing various sorting strategies and understanding how Big-O notation applies to the sequence of generated operations rather than classical array-based algorithms.

## Instructions

### Compilation
To compile the project, simply run the following command at the root of the repository:

```make```

```make bonus```

The Makefile also supports the standard rules: clean, fclean, and re.

### Execution
Run the program by passing a list of integers as arguments. The first argument will be at the top of stack a.

```./push_swap 2 1 3 6 5 8```

### Strategy Selectors
You can force the program to use a specific sorting strategy by passing an optional flag before the integer list. If no flag is provided, ```--adaptive``` is used by default.
- ```--simple```: Forces the use of the $O(n^2)$ algorithm.
- ```--medium```: Forces the use of the $O(n\sqrt{n})$ algorithm.
- ```--complex```: Forces the use of the $O(n \log n)$ algorithm.
- ```--adaptive```: Forces the use of the adaptive algorithm based on the measured disorder.

### Benchmark Mode
You can use the ```--bench``` flag to display performance metrics on the standard error (stderr). This will output the computed disorder percentage, the strategy used, and the total count of each operation type.

```./push_swap --bench --adaptive 4 67 3 87 23```

### Bonus: Checker Program
A custom checker program is included to verify if the instructions generated by push_swap actually sort the stack correctly.

```ARG="4 67 3 87 23"; ./push_swap $ARG | ./checker $ARG```

If the output is ```OK```, the stack is successfully sorted. Otherwise, it will print ```KO``` or ```Error```.

## Algorithms

As per the project requirements, four distinct sorting strategies have been implemented. The efficiency is measured in the number of Push_swap operations generated.

### Simple - Insertion Sort Algorithm

This strategy implements an adaptation of the Insertion Sort algorithm to fulfill the $O(n^2)$ complexity class requirement. It is primarily designed for small datasets or lists with a low disorder metric (disorder < 0.2). The algorithm typically works by iteratively finding elements in stack a and placing them in their correct sequential position to build a sorted sequence. 

```$> ./push_swap --simple 5 4 3 2 1```

### Medium - Chunk Sort Algorithm $O(n\sqrt{n})$

For medium-level disorder configurations (0.2 $\le$ disorder < 0.5), this algorithm falls into the $O(n\sqrt{n})$ complexity class. It utilizes a chunk-based sorting approach where the stack is divided into $\sqrt{n}$ chunks based on value ranges. Elements are systematically pushed to stack b chunk by chunk, which significantly reduces the search space before they are sorted and pushed back to stack a. 

```$> ./push_swap --medium 4 67 3 87 23```

### Complex - Radix Sort Algorithm $O(n \log n)$

This strategy implements a Radix Sort adaptation (such as LSD or MSD) to achieve an $O(n \log n)$ algorithmic complexity. It is highly optimized for large stacks (e.g., 100 or 500 numbers) and scenarios with a high disorder metric (disorder $\ge$ 0.5). By evaluating the numbers in base-2 (binary), it shifts elements between stack a and stack b bit by bit, allowing it to efficiently handle massive data inputs within the operation limits. 

```$> ./push_swap --complex 4 67 3 87 23```

### Adaptive

This strategy calculates a disorder metric (a value between $0$ and $1$ representing how far the initial stack is from being sorted) and dynamically selects the most appropriate algorithm:

- Low disorder (< 0.2): Selects the $O(n^2)$ algorithm.
- Medium disorder (0.2 $\le$ disorder < 0.5): Selects the $O(n\sqrt{n})$ algorithm.
- High disorder ($\ge$ 0.5): Selects the $O(n \log n)$ algorithm.
